# 入力文字の共通ルール

## 文字集合

- 半角英字: A–Z、a–z。
- 半角数字: 0–9。
- 半角記号: 以下の30種類。表示上の区切りスペースは含めない。

```text
! @ # $ % ^ & * ( ) _ + - = [ ] { } ; : ' " , . < > / ? \ ~
```

バッククォート・縦棒・空白・全角文字はこの記号集合に含めない。各入力項目は使用する文字集合または部分集合を個別設計で明示する。記号30種類をすべての項目に自動適用しない。

## 手入力Codeの標準ルール

| 項目 | ルール |
|---|---|
| 英数字 | 半角英字・数字 |
| 記号 | ハイフンとアンダースコア（上記共通集合の部分集合） |
| 保存・表示 | 前後空白を除去した入力表記を保持。大小文字は変換しない |
| 重複判定・Code検索 | ASCII英字の大小文字を区別しない。検索は部分一致でなく完全一致 |
| 空白 | 前後を除去してから検証。内部の空白は拒否 |
| 長さ | 正規化後1〜20文字。ASCIIのみなのでバイト数・コードポイント数は一致 |

これは採番仕様ではない。この標準を採用する項目は個別設計から参照する。名称・自由入力・パスワード・外部指定の識別子へ自動適用しない。異なる記号集合や長さが必要な項目は個別設計で指定する。

### 正規化・比較

FEとBEで共通の順序（前後空白除去→文字種・長さ検証→比較）を使う。BEでも必ず実行する。
前後から除去する空白集合はFE・BEで同一とし、最初の実装で一覧と共有テストを固定する。内部の空白や制御文字を勝手に削除したり、全角文字を半角化したりしない。

DBには正規化後の値を保存し、NOT NULL・文字種/長さのCHECKと大小文字を区別しない一意インデックスを設定する。ASCII比較を確実にする照合順序を詳細設計で揃える。PostgreSQLの例は `lower(code COLLATE "C")` の一意インデックスで、検索も同じ式に対する等値比較とする。比較用の小文字値で元の表示を置き換えない。予約値も同じ比較規則を使う。

標準Codeの許容条件は1〜20文字かつ各文字がASCII英数字・ハイフン・アンダースコアであること。正規表現は各処理系で文字列全体を検証し、末尾改行等を許容しない。DBの例は `CHECK (char_length(code) BETWEEN 1 AND 20 AND code COLLATE "C" !~ '[^A-Za-z0-9_-]')`。

### 詳細設計・実装時の確認

個別設計・OpenAPI・Domain・DB・FEを揃える。空、1文字、20文字、21文字、許可記号、対象外記号、前後/内部空白、全角、大小文字だけ異なる重複・検索・予約値をテストする。既存データへ導入する際は、正規化後の重複と不正値を確認し、一意インデックス作成前に解消方針を決める。
