# 管理画面のデザインルール

管理画面（admin）のモックと実装の各画面で、同じ意味の操作には同じボタンの見た目を使い、同じ役割の文字には共通の文字サイズを使う。新規画面の作成・既存画面の修正時に適用する。

色・部品はデジタル庁デザインシステム（`frontend/packages/ui` と `@digital-go-jp/tailwind-theme-plugin` のトークン）を使い、色の値を画面ごとに書かない。公開画面（public）は対象外（Apple HIG に従う。[`frontend/architecture.md`](../../frontend/architecture.md) §4）。

## ボタンの見た目

| 操作 | `Button` の `variant` | 色のトークン |
|---|---|---|
| 新規作成・保存・登録 | `solid-fill` | 背景 `key-900`、ホバー `key-1000`、押下 `key-1200`、文字は白 |
| キャンセル・検索・戻る・確かめるなどの補助操作 | `outline` | 枠線と文字 `key-900`、ホバーの背景 `key-50` |
| 削除 | `solid-fill` にエラー色を重ねる | 背景はデザインシステムのエラー色（`error-1`）、文字は白 |

- 「新規追加」「保存する」など、同じ意味の別表記にも適用する。
- 行内の削除も、削除の見た目にする。
- 「キャンセル」は入力を取りやめる補助操作を指す。
- 無効なボタンは `aria-disabled` と `disabled` を付け、デザインシステムの無効の見た目（`solid-gray` 系）にする。ホバーしても有効時の色に変えない。
- 色に加えて「新規作成」「保存」「検索」「削除」などの文言で操作を示す。

## 上限に達したボタンのホバー

- 件数上限などで操作できない場合は、ボタンを非活性にする。ホバー・クリック・キーボード操作で実行できる状態にはしない。
- ホバーしても、非活性の見た目を維持する。
- ボタンにホバーすると、非活性の理由をツールチップで表示する。残りの件数をボタンに表示しない。
- ボタン自体は `disabled` のままにし、外側の要素でホバーを受け取る。外側の要素に `tabindex` を付けない。説明の表示はホバー時のみとし、キーボードのフォーカスによる表示は設けない。
- ボタンを `aria-describedby` で説明に関連付ける。ツールチップには `role="tooltip"` を付ける。
- 説明はボタンの下に表示し、画面端で切れない位置に配置する。
- ポインターがボタンまたは説明にある間は説明を表示する。Escape で閉じられるようにする。
- 画面上にも理由を表示し、ホバーだけに説明を依存させない。

## 名前の文字数

- 管理画面で登録するデータの名前（分野タグの名前など）は、上限を入力欄の近くに表示するか、入力欄のラベルに明記する（例:「30文字以内」）。
- 入力欄に上限の制限を設け、保存時にも文字数を確認する。上限ちょうどは保存でき、上限を超えたら保存しない。
- 上限を超えた場合の文言は「○○は N 文字以内で入力してください」とする。
- 「1文字」は Unicode のコードポイントで数える。OpenAPI の `maxLength`、Go の `utf8.RuneCountInString`、PostgreSQL の `VARCHAR(N)`（UTF-8）、FE の入力制限・カウンター・検証を揃える。見た目の 1 文字（書記素クラスタ）ではないため、結合文字や複数コードポイントの絵文字は複数と数える。
- FE の `String.length`・生成 zod の通常の長さ検証・HTML の `maxlength` はそのまま採用しない。UTF-16 単位の制限で有効な文字列を拒否しないよう、生成工程と共通入力処理で対応する。詳細は [`frontend/architecture.md`](../../frontend/architecture.md) §9。
- ASCII・日本語・補助平面の絵文字・結合文字の上限ちょうど／上限 +1 の境界について、FE・HTTP 境界・Domain・DB の結果が一致することを実装時に検証する。IME 変換途中で文字を切断しない。

## 管理画面の文字

フォントはデザインシステムのテーマに従う（`packages/ui` の Tailwind preset）。見た目の印象でサイズを決めず、次の役割に対応するトークンを使う。

| 役割 | トークン |
|---|---|
| 画面タイトル | `std-24B-150` |
| セクション見出し | `std-17B-170` |
| 本文・一覧表のデータ・入力ラベル・入力文字・通常ボタン | `std-16N-170` / ボタンは `oln-16B-100` |
| 一覧表の列見出し・件数表示・ページボタン・一時通知 | `std-14N-170`（見出しは太字） |
| 補助説明・入力エラー・状態表示・パンくず | `std-14N-170` |
| 行内の補足・文字数カウンター | `dns-14N-130` |

画面ごとに上部メニューやサイドバーの文字を小さくしない。太さや補助色で情報の強弱を表し、同じ役割の文字サイズを揃える。

## 管理画面のボタンサイズ

- 通常ボタン：`Button` の `size="md"`（最小高さ 48px）。
- 行内などの小さいボタン：`size="sm"`（最小高さ 36px。タップ領域は 44px を確保）。
- キーボード操作時にフォーカスを見分けられる表示を設ける（`Button` の既定のフォーカスリング）。

モックのコードを本番コードへ流用しない。本番では、このルールに従って共通 UI 部品を実装する。

## 重要な処理の確認ダイアログ（共通仕様）

削除など、データの消失・利用可否に影響する重要な処理は、実行前に画面内の確認ダイアログを表示する。ブラウザー標準の `confirm` / `alert` ではなく、以下の共通の形を使う。

### 構成と見た目

- 背面を半透明の黒で覆い、中央に白背景・角丸のダイアログを表示する。幅は基本 520px、画面内に収める。件数が増えても縦に伸びないよう対象を要約する。本文が長い場合のみ本文部分をスクロールする。操作ボタンは常に確認できるようにする。
- 上部は処理名を表す見出し（例：「本の削除」「分野タグの削除」）。下に区切り線を置く。
- 本文は、何を実行するか、対象の名前・件数を示す。削除の影響（例：分野タグを消すと付いている本から外れる）も明示する。対象は先頭 3 件まで表示し、4 件以上は「…ほか○件」で残件数を示す。長い名前は 1 行の末尾を「…」で省略し、ホバーで全文を確認できるようにする。省略は表示のみで、処理対象の件数は変えない。
- 下部は上に区切り線を置き、「実行操作」「キャンセル」を並べる。通常のボタンサイズを使う。
- 実行ボタンは「削除」など処理が分かる文言にする。削除は削除の見た目（上の表）にする。
- キャンセルは補助操作の見た目（`outline`）にする。

### 動作

- 確認中は対象データを変更しない。実行ボタンを押した後にだけ処理する。
- 開いた直後のフォーカスはキャンセルに置く。Tab の移動はダイアログ内に限定する。Escape はキャンセルとして閉じ、背面クリックでは実行しない。閉じたら起点の操作へフォーカスを戻す。
- 見出しと説明をダイアログへ関連付け、読み上げでも処理・対象・影響を把握できるようにする。色だけで操作を区別しない。
- キャンセル時は入力・選択・対象データを維持する。
- 実行時は二重送信を防ぐ。成功・失敗を明示し、失敗時は未反映の対象を保持して再試行できるようにする。
- 処理対象がない場合は実行ボタンを出さず、理由と閉じる操作を示す。
