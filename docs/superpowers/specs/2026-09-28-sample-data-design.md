# 起動時の見本データ投入 設計

**日付:** 2026-09-28
**対象:** バックエンド拡張（[要求定義](../../requirements.md) §5 単位1 の「起動時の見本データ投入」）。要件は[要件定義](../../specifications.md) §1.2（見本データに楽天由来の情報を入れない）・§4.3
**変更前の形:** [読んだ本の API 設計](./2026-09-28-reading-api-design.md)、[分野タグ 設計](./2026-09-28-book-tags-design.md)。この文書はそこからの差分だけを書く

## 目的

- README の手順どおりに起動するだけで、見本データ入りの画面を見られるようにする（採用担当が手元で動かす入口）
- ネットワークに繋がらなくても起動できる

## やらないこと

- 管理用の投入コマンド（`make seed` など）。「データが空のときだけ起動時に入る」で要件を満たす
- 既にデータがある DB への追加・上書き
- 見本データへの分野タグの付与（タグの定義は自分で決めてから足す。§4 参照）

## 1. 見本データ

実際に読んだ5冊。書誌（書名・著者・出版社・出版日）は見本データ自身が持ち、外部カタログに頼らない。

| 書名 | ISBN |
|---|---|
| 徹底攻略 AWS認定 ソリューションアーキテクト アソシエイト教科書 第3版 | 9784295016090 |
| 改訂新版 良いコード／悪いコードで学ぶ設計入門 | 9784297146221 |
| プロダクトマネジメントのすべて | 9784798166391 |
| データ指向アプリケーションデザイン 第2版 | 9784814401802 |
| ネットワークはなぜつながるのか 第2版 | 9784822283117 |

- 書誌の値は実装時に openBD から写す。データ指向アプリケーションデザイン第2版は openBD に未登録（2026-09-28 時点）のため、出版社の書誌ページから写す
- 楽天由来の情報（書影 URL・商品ページ URL）は持たない（§1.2）
- **一言まとめ・感想・評価は仮の値**（一言まとめ・感想は「（準備中）」、評価は3）。自分で書いた文章に差し替えるまで、この状態を要件（§4.3「架空の感想は入れない」）を満たしていないものとして扱う。データファイルの冒頭にその旨を書く

要件定義 §4.3 の「4冊」を「5冊」に、データ指向アプリケーションデザインを第2版に直す（実際に読んだのが第2版で、5冊目があるため）。

## 2. 投入の流れ

`cmd/api` の `run()` で、DB に接続した直後・HTTP サーバを立てる前に呼ぶ。

1. 本が1冊でもあれば何もしない（`book.Query.FindList` の `Total` で判定）
2. 見本データの各冊を VO で組み立て、`book.Repository.Create` で保存する
3. 各冊の書影は、既存の外部カタログ（`BookCatalog`、openBD → 楽天）に問い合わせて取れたときだけ付ける。問い合わせの失敗・該当なしは warn ログを出して書影なしで保存する（起動は止めない）

| 決めごと | 理由 |
|---|---|
| 登録のユースケース（`RegisterUsecase`）は使わず、Repository に直接書く | 登録ユースケースは書誌を外部カタログから取る前提で、openBD に無い本（第2版）やネットが無いときに登録できない。見本データは書誌を自前で持つので、その前提が合わない |
| 見本データが VO の検証で弾かれたら起動を失敗させる | データはリポジトリに固定で置くもので、弾かれるのは作り間違い。テストで全件の検証を通しておく |
| `Create` が `ErrConflict`（同じ ISBN）を返したら、その冊は飛ばして続ける | 複数のプロセスが同時に空の DB で起動したときに、先に入れた側を正とするため |
| 書影の問い合わせは既存の `catalogTimeout`（5秒）をそのまま使う | 空の DB での初回起動だけに走る処理で、専用の設定を増やすほどではない |

openBD に未登録の本は、外部カタログの問い合わせが「該当なし」になるため書影が付かない（楽天の書影は openBD に書誌があるときだけ補う作りのため）。openBD に登録されれば、その本を更新したときに書影が付く。

## 3. 置き場所

| ファイル | 中身 |
|---|---|
| `backend/cmd/api/sample_data.go` | 見本データ（Go の構造体リテラル）と投入関数 `seedIfEmpty` |
| `backend/cmd/api/main.go` | `run()` から `seedIfEmpty` を呼ぶ |

- 5冊程度のデータに新しいパッケージ・ユースケースの型は作らない。起動時に1回だけ走る組み立ての処理なので、DI と同じ `cmd/api` に置く
- JSON/YAML ファイルにはしない（読み込みと型の変換が増えるだけで、Go のリテラルでも差し替えやすさは同じため）

## 4. 分野タグ

見本データには当面タグを付けない。タグの名前（粒度）を自分で決めたら、見本データにタグの定義と各冊への付与を足す（タグが無いと分野別の集計の画面が空になるため、公開画面（単位2）に入る前に足す）。

## 5. テスト

| 対象 | 確かめること |
|---|---|
| 見本データ | 全冊が VO の検証を通る、ISBN の重複がない、楽天由来の情報を持たない（DB 不要の単体テスト） |
| `seedIfEmpty`（Fake） | 空なら全冊を保存する、1冊でもあれば何もしない、書影の問い合わせが失敗・該当なしでも保存する、`ErrConflict` の冊を飛ばして続ける、Repository のその他のエラーは返す |
| 起動（実 DB） | 空の DB で起動すると5冊入り、もう一度起動しても増えない |

## 6. PR の分け方

1本（見本データ・投入関数・`run()` からの呼び出し・要件定義の冊数の修正・README の手順）。
