# 公開画面（単位2）の設計

**日付:** 2026-09-29
**参照:** [要件定義 §2](../../specifications.md#2-公開画面誰でも見られる)、[画面イメージ](../../design/public-screens/README.md)

> **変更（2026-09-29）:** 楽天ブックスは撤去したため、この設計の楽天のクレジット・商品ページ・注記の表示は消した（[書影の取得元の見直しの設計](./2026-09-29-cover-sources-design.md)）。

誰でも見られる3画面（一覧・詳細・分野別の集計）を `frontend/web` に作る。見た目は [画面イメージ](../../design/public-screens/README.md) を正とし、振る舞いは要件定義 §2 を正とする。API は単位1で揃っているので、バックエンドは変えない。

## 画面と URL

| 画面 | path | 使う API |
|---|---|---|
| 一覧 | `/`（`?q=<キーワード>&tag=<タグID>`） | `GET /api/books`、`GET /api/tags` |
| 詳細 | `/books/:id` | `GET /api/books/{id}` |
| 分野別の集計 | `/tags` | `GET /api/tags/counts` |
| 上記以外 | `*` | なし（見つからない旨と一覧へのリンク） |

- 検索キーワードと絞り込みは **URL のクエリを正**にする（Zustand に持たない）。分野別から `/?tag=<id>` へ移るだけで絞り込んだ一覧になり、戻る・再読み込みでも状態が残るため
- `tag` が数値でない・1未満なら、絞り込みなしとして扱う（API の 400 を画面に出さない）

## 一覧

- 検索は `<form role="search">` の送信で `q` を URL に反映する。前後の空白を除いて空なら `q` を消す（全件に戻る）
- 分野タグはボタン群（`aria-pressed`）。「すべて」で `tag` を消す。タグ一覧の取得に失敗しても本の一覧は出す（タグのボタンだけ出さない）
- 1回に20冊読む。「もっと見る」で続きを読み、`読み込んだ冊数 >= total` になったらボタンを出さない。「N冊中 M冊を表示」を添える
- 読み込みは Orval の **infinite query 生成**（`getApiBooks` だけ `useInfinite: true`、`useInfiniteQueryParam: 'offset'`）を使う。Query フックを手書きしない方針（`frontend/architecture.md` §5）を守るため。次の offset は feature の hook で `offset + items.length`、`total` 以上なら `undefined`
- `q`・`tag` が変わると Query のキーが変わり、先頭から読み直す（要件「結果の先頭から表示し直す」）
- カード全体を詳細へのリンクにする

## 詳細

- 書名・著者・出版社・出版日・ISBN・書影・評価・分野タグ・一言まとめ・感想（改行を保つ）
- 値が無い項目（出版社・出版日）は行ごと出さない。書影は `coverUrl` があればその画像、無ければ「書影なし」の枠を出す
- Amazon リンクは `amazonUrl` があるときだけ「Amazonで見る」
- Google Books の書影のときの表示（「Powered by Google」と、その本の Google Books のページへのリンク）は、[書影の取得元の見直しの設計](./2026-09-29-cover-sources-design.md) の PR-C で足す
- 外部リンクは `target="_blank" rel="noopener noreferrer"`
- API が 404 なら「この本は見つかりませんでした」と一覧へのリンク。ほかのエラーは共通のエラー表示（再試行つき）

## 分野別の集計

- `GET /api/tags/counts` の順（冊数の多い順）のまま並べ、各行を `/?tag=<id>` へのリンクにする
- 棒の長さは最大冊数に対する割合。棒は飾りなので `aria-hidden`、冊数は文字で出す
- 0件（本が付いたタグが無い）なら「分野タグの付いた本はまだありません」

## 共通

- ヘッダー: サイト名「読んだ本」（`/` へ）と、ナビ「一覧」「分野別」（今いる画面に `aria-current="page"`）
- フッター: 「書誌・書影: openBD」
- 画面の状態（要件 §2.4）は `components/` の共通部品にする（3画面で同じ見た目・同じ理由で変わるため）
  - `LoadingState`: `role="status"` で「読み込み中…」
  - `EmptyState`: 見出しと次にすべきことの文言、任意の操作ボタン
  - `ErrorState`: `role="alert"`、分かる言葉の文言、「再試行」ボタンで `refetch`
  - 一覧の追加読み込み中は末尾に「続きを読み込み中…」、「もっと見る」は無効にする
- 評価は `RatingStars`（`★` と `☆`、`aria-label="評価 N / 5"`）
- 既存の `features/home` と `ComingSoonPage` は消す（仮置きの画面のため）

## 0件の文言

| 条件 | 文言 | 操作 |
|---|---|---|
| 本が1冊も無い（`q`・`tag` なし） | まだ本が登録されていません | なし |
| 検索・絞り込みの結果なし | 条件に当てはまる本はありません。キーワードを変えるか、分野タグを「すべて」に戻してください。 | 「検索と絞り込みを外す」（`/` へ） |

## テスト

`frontend/architecture.md` §8 と `docs/rules/testing.md` に従う。API は生成 MSW ハンドラを `server.use(get…MockHandler(fixture))` で上書きする。

- 純関数は単体（次の offset の計算、`tag` クエリの解釈、`q` の正規化、棒の割合）
- 画面ごとに: 読み込み中 / 成功 / 0件 / エラー→再試行で取り直す
- 一覧: 検索の送信で `q` 付きの API が呼ばれる、空白だけの送信で `q` が消える、タグを押すと `tagId` 付きで呼ばれ「すべて」で外れる、「もっと見る」で offset 20 が呼ばれ最後まで読むとボタンが消える、タグ一覧が失敗しても本は出る
- 詳細: 書影の有無（画像か「書影なし」の枠か）、Amazon リンクの有無、404 で見つからない表示
- 分野別: 各行のリンク先が `/?tag=<id>`、0件の文言
- 共通: ナビの `aria-current`

## やらないこと

- スクロールでの自動読み込み（「もっと見る」ボタンにした。操作の結果が明示的で、テストも書きやすいため）
- 検索の入力中の自動検索（送信で検索する）
- 管理画面（単位3）
