# 書籍の表紙画像を S3 に保存し、ローカルは LocalStack 4.9 で代替する

**日付:** 2026-09-28
**状態:** 不採用（2026-09-28 に [外部カタログの書影を使う方式](./2026-09-28-book-cover-from-external-catalogs.md) へ置き換え）
**カテゴリ:** library / infra
**参照:** 書籍の画像・Amazon リンク追加の PR

## 背景・経緯

書籍に表紙画像を持たせるにあたり、画像の保存先として S3 互換のオブジェクトストレージを使い、ローカルでも同じ API で動かしたい。ローカルの S3 互換サービスとして LocalStack を選んだが、検証時点（2026-09）で `localstack/localstack:latest`（2026.x 系）は Pro 版のイメージになっており、`LOCALSTACK_AUTH_TOKEN` が無いと `License activation failed` で終了した。コミュニティ版の `localstack/localstack:4.9` はトークン無しで S3 が起動することを確認した。

## 決定

- 画像の保存先は S3。Go からは **aws-sdk-go-v2**（`config` / `credentials` / `service/s3`）で操作する。`endpoint` を指定したときだけパス形式（`UsePathStyle`）で接続し、未指定なら AWS S3 に向ける
- ローカルは docker compose に **LocalStack を `4.9` 固定**で追加し、起動時にバケット `book-images` を作成する
- 画像はアップロード API で受け取りバックエンドから S3 に保存する。DB にはオブジェクトキーだけを保存し、取得時に15分有効の署名付き URL を返す（バケットは公開しない）
- アップロードのたびに新しいキーで保存し、書籍の差し替えに成功したら古いオブジェクトを消す（上書きしないことで発行済み URL・キャッシュが別の画像を返さないようにする）
- 古い画像・保存に失敗した新しい画像の削除に失敗した場合はログ（warn）に残すだけとし、孤立オブジェクトの定期清掃は**当面行わない**。コードレビューで清掃の検討を指摘されたが見送った。孤立するのは削除失敗時だけで、影響はストレージ容量のみ（書籍の整合性は崩れない）。本番のストレージが決まった時点で、S3 のライフサイクルルールやログからの清掃ジョブを改めて判断する

## 検討した代替案

| 案 | 概要 | 却下理由 |
|---|---|---|
| A（採用） | LocalStack 4.9 固定 | トークン不要で動作確認済み。ローカル専用のため更新停止の影響は小さい |
| B | LocalStack 最新版 + 認証トークン | 開発者ごとにアカウント・トークンの用意が必要になり、CI で契約テストを動かすにもトークン管理が要る |
| C | MinIO | コミュニティ版の配布方針が変わり、Docker イメージの更新が止まっているため LocalStack 以上の利点がない |
| D | 公開バケットの URL を DB に保存 | 最も単純だが、画像が誰でも取得できてしまう |
| E | 署名付き URL でフロントから S3 に直接アップロード | 大きなファイル向けだが、5MB 以下の表紙画像には手順が増えるだけ |

## 判断基準（任意）

LocalStack 4.9 はローカル専用の代替で、本番は AWS S3 を想定する。4.9 で動かない S3 の機能が必要になった、または脆弱性が問題になった時点で、B か別の S3 互換 OSS への差し替えを再検討する。
