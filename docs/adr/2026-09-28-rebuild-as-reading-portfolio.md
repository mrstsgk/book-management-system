# 「自分が読んだ本を紹介するポートフォリオ」として、基盤だけ残して作り直す

**日付:** 2026-09-28
**状態:** 採用
**カテゴリ:** architecture
**参照:** なし（口頭決定）。撤去するもの: [書籍の表紙画像を S3 に保存し、ローカルは LocalStack 4.9 で代替する](./2026-09-28-book-image-storage-s3-localstack.md)

## 背景・経緯

Go 版の書籍・著者 API は、旧 Kotlin 実装（書籍と著者を管理する課題）の仕様をそのまま引き継いだ。その後、目的が「自分が読んだ本を紹介するポートフォリオ」に変わり、画像アップロード・外部カタログ（openBD・楽天ブックス）の書影・書籍一覧・著者の候補などを継ぎ足していったが、次の点で目的と中心がずれていた。

- 書籍の登録に、先に著者を作ってその ID を指定する必要がある（紹介したい本を登録する手間が大きい）
- 外部カタログの著者情報は著者と訳者の区別がなく（ONIX の `ContributorRole` が空）、書式も「姓, 名, 生年-」とばらばらで、著者情報が無い本もある。著者マスタに自動では入れられない
- 著者の生年月日・出版状況・価格など、紹介には使わない項目と業務ルールを抱えている
- 自分で撮影した表紙の公開は著作権上避けるべきで、画像アップロードは不要

本番のデータは無く、作り直しのコストが最も低い時期である。

## 決定

- 基盤（リポジトリ構成、CI、開発ルール・ADR・hook、backend の共通部分、frontend の骨格）だけを残し、書籍・著者のドメイン・UseCase・API・DB 実装、画像アップロード（S3・LocalStack）、旧マイグレーションを撤去する
- 新しい中心は「読んだ本」1件 = ISBN で外部カタログから取得した書誌（書名・著者名の文字列・出版社・発売日・書影）＋自分の**感想**と**評価**。著者は独立したエンティティにせず、提供元の文字列のまま持つ
- 価格は持たない（紹介には不要で、カタログの値は税込・税抜が混ざる）。Amazon のリンクは ISBN から導出する
- 閲覧は誰でも、登録・更新・削除は自分だけ（簡易な認証）
- ISBN・書影・外部カタログのゲートウェイ・一覧の取得範囲など、旧 PR で作った部品のうち新しい中心に合うものは流用する
- マイグレーションは本番データが無いため 000001 から作り直す。ローカル DB は作り直す（`make db-down` の後に volume を削除して `make db-up migrate-up`）

## 検討した代替案

| 案 | 概要 | 却下理由 |
|---|---|---|
| A（採用） | 基盤だけ残して作り直す | 目的に合わない仕様と業務ルールを持ち越さずに済み、本番データが無い今ならコストが小さい |
| B | 書籍・著者のモデルを残して感想などを足す | 著者マスタ・生年月日・出版状況など、紹介に不要なものを保守し続けることになる |
| C | 書籍に著者名の文字列を持たせる形に既存コードを段階的に改修 | 変更範囲がほぼ全体に及び、作り直しと手間が変わらない一方、旧仕様の痕跡が残る |

## 判断基準（任意）

モデルは「このシステムで何を見せたいか」から決める。前身のシステムや課題の仕様を引き継ぐかどうかは、今の目的に照らして毎回判断する。
