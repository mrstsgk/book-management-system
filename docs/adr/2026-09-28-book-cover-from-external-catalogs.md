# 書影は外部カタログ（openBD・楽天ブックス）の URL を表示し、自前の画像アップロードをやめる

**日付:** 2026-09-28
**状態:** 採用
**カテゴリ:** architecture / library / infra
**参照:** 一部を置き換えられた: [楽天ブックスは書影を補う用途だけに使う](./2026-09-28-rakuten-for-cover-only.md)（openBD に該当が無いとき楽天で補う部分）、[読んだ本の紹介としての作り直し](./2026-09-28-rebuild-as-reading-portfolio.md)、置き換え前: [書籍の表紙画像を S3 に保存し、ローカルは LocalStack 4.9 で代替する](./2026-09-28-book-image-storage-s3-localstack.md)

## 背景・経緯

表紙画像は API でアップロードして S3（ローカルは LocalStack）に保存する方式にしていた。しかし、このシステムは自分が読んだ本をポートフォリオとして公開・紹介する用途で、自分で撮影・スキャンした表紙（装丁・イラストの著作物）を公開すると著作権上の問題がある。許諾のある提供元の書影を使う方式に切り替える。

検証時点（2026-09）で確認した事実:

- openBD: 登録・キー不要。書誌・書影は「本の販促・紹介目的に限り」利用できる。データを改変しない、変更をできるだけ早く反映する、削除要請に従う、が条件。ただし書影がある本は少なく、試した12冊中1冊、登録予定の技術書4冊はすべて書影なし（書誌は全冊取得できた）
- 楽天ブックス書籍検索 API: 無料。アプリ ID とアクセスキー（`openapi.rakuten.co.jp`）が必要。書影（`largeImageUrl`）あり。画面にクレジット表記が必要
- Amazon PA-API 5.0: 2026年5月に提供終了。後継の Creators API は「過去30日以内の適格な売上10件以上」が利用条件で、個人のポートフォリオでは満たせない
- Google Books API: キーなしでは共有の上限に達していて検証できず
- 紙の本の Amazon の ASIN は ISBN-10 と一致する（登録予定の4冊で `https://www.amazon.co.jp/dp/{ISBN-10}` が正しい商品ページを開くことを確認）

## 決定

- 読んだ本は ISBN（13桁で保持）で登録する。登録時にサーバが ISBN で外部カタログを引き、書誌（書名・著者・出版社・発売日）と書影の URL・提供元（`openbd` / `rakuten`）を保存する。画像そのものは保存・加工しない。感想・評価の更新のたびに書誌と書影を取り直し、提供元の変更を反映する
- カタログは openBD を優先し、openBD に書影が無い（または該当が無い）ときだけ楽天で補う。楽天のキーは任意で、未設定なら openBD だけで動く
- 登録はカタログに該当が無ければ 400（書名すら分からないため）。更新ではカタログの障害や該当なしで感想の更新を止めず、今の書誌・書影のままにする
- Amazon のリンクは手入力させず、ISBN-10 から導出する（保存しない）
- `GET /api/catalog/{isbn}` を登録前の確認用に用意する。外部カタログへの中継を誰にでも開放しないよう、書き込み系と同じく管理者トークンを必要とする

## 検討した代替案

| 案 | 概要 | 却下理由 |
|---|---|---|
| A（採用） | openBD + 楽天で書影の URL を取得して表示 | 許諾のある書影だけを使え、キーが無くても openBD だけで動く |
| B | 自前アップロード（S3）を残す | 自分で撮った表紙の公開は著作権上避けるべきで、残す理由が無い |
| C | Amazon Creators API | 売上実績の利用条件を満たせない |
| D | openBD だけ | 書影がある本が少なく、登録予定の本はすべて書影なしになる |

## 判断基準（任意）

書影・書誌は「提供元が紹介目的での表示を許諾しているか」を最優先に選ぶ。画像を自前で保存する方式は、許諾を得た画像（自作のものなど）を扱う必要が出たときに改めて検討する。
