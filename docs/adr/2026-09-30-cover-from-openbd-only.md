# 書影は openBD だけから取り、無ければ書影なしにする（Google Books は使わない）

**日付:** 2026-09-30
**状態:** 採用
**カテゴリ:** architecture / library
**参照:** [設計](../superpowers/specs/2026-09-29-cover-sources-design.md)、一部を置き換え: [書影は Google Books → openBD の順で取り、楽天ブックスは撤去する](./2026-09-29-cover-from-google-books-and-openbd.md)（Google Books の部分。楽天の撤去はそのまま有効）、閉じた PR: #93

## 背景・経緯

前の ADR で、書影を Google Books → openBD の順で取ることにした。Google Books の Gateway（#89）まで入れたあと、配線の PR（#93）を検証する段階で、Google Books も楽天と同じく API キーが要ることが問題になった。公式ドキュメントでは公開データの要求にもキーかアクセストークンが必要で、キーを付けない呼び出しは全員で共有する日次の上限を超えて 429 になる。

このリポジトリはキーを置かないので、clone して動かす人の環境では Google Books の書影は出ない。楽天を撤去した理由（キーを持たない人の環境で書影が出ない）は Google Books にもそのまま当てはまり、画面のクレジットとリンクという Google Books のためだけの表示も増える。

## 決定

- 書影は **openBD だけ**から取る。openBD に書影が無ければ書影なし（画面は「書影なし」の枠）
- openBD の書影は、版元ドットコムで出版社が「利用可」にした書影だけなので、キーなしで誰の環境でも同じに見え、規約上も紹介目的で使ってよい
- Google Books の配線（#93）は閉じ、使われていない `gateway/googlebooks`（#89）は消す
- 書影を出したい本は、openBD に書影がある本（出版社が「利用可」にしている本）を選ぶ
- openBD からの削除要請には、画像を保存せず提供元の URL を都度表示するだけで対応できる。書誌・書影は登録・更新のたびに openBD から取り直すため、openBD 側の削除・変更は次の登録・更新で反映される（削除要請を受けて何かを消す専用の仕組みは持たない）

## 検討した代替案

| 案 | 概要 | 却下理由 |
|---|---|---|
| A（採用） | openBD だけ。無ければ書影なし | キーが要らず、誰の環境でも同じ。取得元のための仕組み（期限・削除・クレジット）が無い |
| B | Google Books → openBD（前の ADR の決定） | API キーが必要で、キーを持たない人の環境では書影が出ない。Google のロゴと本ごとのリンクの表示も要る |
| C | 公式ドキュメントに無い、Google のキー不要の画像 URL（`books.google.com/books/content?vid=ISBN…`） | 予告なく使えなくなりえる。書影の無い本にはダミー画像が返り、見分ける処理が要る。規約上の扱いがはっきりしない |

## 判断基準（任意）

書影の取得元は「キーを持たない人の環境で同じに見えるか」を最初の条件にする。キーが要る取得元は、この条件を満たさないので入れない。
