# 要件定義

[要求定義](./requirements.md)を満たすために、システムと開発の進め方が満たすべきことの正。各要件は「満たしたかどうか」を確かめられる形で書く。どう作るかは [`architecture.md`](./architecture.md) 以下の各文書に書く。

文字数などの細かい上限は、各単位の設計で決めてここに足す。

## 1. 読んだ本

### 1.1 持つ情報

| 項目 | 入手元 | 要件 |
|---|---|---|
| ISBN | 自分で入力 | 13桁または10桁（ハイフン可）。同じ ISBN は二重に登録できない |
| 書名・著者・出版社・出版日 | openBD | ISBN から自動で取得する |
| 書名の上書き | 自分で入力（任意） | 上書きした書名があれば、画面ではそれを書名として見せる。外部カタログを取り直しても上書きは消えない。上書きを消せば外部カタログの書名に戻る |
| 書影 | 外部カタログの URL | 画像は保存しない。取得元は §1.2 |
| Amazon リンク | ISBN から導出 | ISBN-10 にできる本だけ持つ。保存しない |
| 一言まとめ | 自分で入力（必須） | 一覧で見せる短い要約 |
| 感想 | 自分で入力（必須） | 詳細で見せる本文。1〜5000文字、改行できる |
| 評価 | 自分で入力（必須） | 1〜5 の整数 |
| 分野タグ | 定義済みのタグから選ぶ | 1冊に複数付けられる。付けなくてもよい |

- openBD に無い ISBN は登録できない（書名すら分からないため）
- 感想・評価などを更新するとき、書誌と書影も外部カタログから取り直す。取り直せなければ今の書誌と書影のままにし、更新は止めない
- 同時に同じ本を更新したときは、後から保存した方が失敗する（上書きで消えない）

### 1.2 書影の取得元

書影は提供元の URL をそのまま表示するだけで、画像は保存しない。取得元ごとの保持期限や削除の指示に合わせる仕組みは持たない（楽天ブックスは撤去した。[ADR](./adr/2026-09-29-cover-from-google-books-and-openbd.md)。書影は openBD だけから取り、無ければ書影なし。[ADR](./adr/2026-09-30-cover-from-openbd-only.md)）。

- 書影は openBD から取る。openBD に書影が無い本は書影なし（画面は書影なしの枠を出す）
- 登録と更新のたびに、書誌と書影を取り直す
- 画像そのものは保存せず提供元の URL を都度表示するだけなので、openBD 側で書誌・書影が削除・変更されても、次にその本を登録・更新した時点で反映される（openBD からの削除要請に対応する専用の仕組みは持たない）

### 1.3 分野タグ

- タグは自分が先に定義し、本にはその中から選んで付ける
- タグの追加・名前の変更・削除ができる。同じ名前のタグは作れない
- タグを削除すると、そのタグは本からも外れる（本は消えない）

## 2. 公開画面（誰でも見られる）

### 2.1 一覧

- 書影・書名・著者・一言まとめ・評価・分野タグを並べる。新しく登録した順
- キーワードで書名・著者を検索できる。検索を消すと全件に戻る
- 分野タグで絞り込める。「すべて」を選ぶと絞り込みを外せる
- 検索と絞り込みは同時に使える。どちらかを変えたら、結果の先頭から表示し直す
- 冊数が多くても、一覧を分けて読み込める（一度に全件を返さない）。最後まで読んだらそれ以上読み込まない

### 2.2 詳細

- 一覧から本を選ぶと詳細へ移る
- 書名・著者・出版社・出版日・ISBN・書影・Amazon リンク・一言まとめ・感想・評価・分野タグを見せる
- Amazon リンクは ISBN から作る
- 存在しない本を開いたら、見つからないことを伝える

### 2.3 分野別の集計

- 分野タグごとの冊数を見せる
- 集計から分野を選ぶと、その分野で絞り込んだ一覧へ移る

### 2.4 画面の状態（すべての画面に共通）

| 状態 | 要件 |
|---|---|
| 読み込み中 | 読み込み中であることを表示する。追加の読み込み中は、一覧の末尾に表示する |
| 0件 | 本が無い・検索結果が無いことを、次に何をすればよいか分かる文言で表示する |
| エラー | API に届かない・API がエラーを返したときに、分かる言葉で表示し、再試行できる。再試行すると取得し直す |

PC で見ることを主とし、スマホの幅でも崩れないようにする。

## 3. 管理画面（自分だけ）

### 3.1 ログイン（後回し）

- 当面はログイン画面を持たない。管理者トークンは frontend の環境変数 `VITE_ADMIN_TOKEN` から読む。ユーザー管理は持たない（[ADR](./adr/2026-09-30-admin-token-from-env.md)）
- トークンが設定されていなければ、管理画面で書き込めないことと設定のしかたを伝える
- 画面をビルドして公開するときは、トークンを入力するログインに置き換える

### 3.2 本の登録

- ISBN を入れると、登録前に外部カタログの書誌と書影を確かめられる
- 一言まとめ・感想・評価・分野タグを添えて登録する
- 入力の誤り（必須の未入力・上限超え）は項目ごとに伝え、登録しない
- カタログに無い ISBN、登録済みの ISBN は、その理由を伝えて登録しない

### 3.3 本の編集・削除

- 書名の上書き・一言まとめ・感想・評価・分野タグを変えられる
- 他で先に更新されていたら、そのことを伝えて保存しない
- 削除は確認してから行う

### 3.4 タグの管理

- タグの一覧・追加・名前の変更・削除ができる
- 削除するときは、付いている本から外れることを確認してから行う

## 4. 非機能要件

### 4.1 コードの品質

| 要件 | 確かめ方 |
|---|---|
| 命名が言語とリポジトリの規約に沿っている | lint（Go: revive、TS: ESLint）とレビュー |
| 関数が複雑になりすぎていない | 循環的複雑度を lint で検査し、上限（10）を超えたら CI を落とす。表形式のテストは対象外 |
| 層の依存の向きが守られている（Domain は他層に依存しない） | [`backend/architecture.md`](../backend/architecture.md) の層構成とレビュー |
| 同じ理由で変わる処理が1か所にまとまっている（DRY）。似ているだけの処理は無理に共通化しない | レビュー |
| 振る舞いを変えたら、同じ場所にテストがある | テストの hook と[テストのルール](./rules/testing.md) |
| テスト・lint・書式・脆弱性・OpenAPI とフロントの型のずれを CI で必ず通す | CI |

### 4.2 チーム開発の進め方

| 要件 | 確かめ方 |
|---|---|
| コミットは1つの論理的な変更ごとに分け、それぞれ単体でビルドできる | [コミットのルール](./rules/git-commit-message.md)とレビュー |
| コミットメッセージに、何をしたかと、必要ならなぜそうしたかが書かれている | 同上 |
| PR のタイトルと本文から、ゴールとマージ前に確かめたことが分かる | [PR のルール](./rules/git-pull-request.md)とテンプレート |
| レビュー指摘は指摘ごとにコミットし、スレッドにコミット ID で返信する | 同上 |
| 自明でない判断は ADR に残す | [ADR のルール](./rules/adr.md)と hook |

### 4.3 動かし方・運用

| 要件 | 確かめ方 |
|---|---|
| README の手順だけで、ローカルに見本データ入りの画面を立ち上げられる | README の手順どおりに起動して確かめる |
| 見本データは、データが空のときだけ起動時に自動で入る。外部カタログに頼らない（書誌も見本データに持つ） | 同上。ネットを切っても起動できる |
| 見本データは実際に読んだ10冊と自分が書いた感想（架空の感想は入れない） | 見本データのファイル |
| 書き込みは管理者トークンで守る。トークンが未設定なら書き込みを受け付けない。閲覧は認証なし | API のテスト |
| 外部カタログの規約（openBD は本の紹介目的に限る）を守る | 画面の確認 |
